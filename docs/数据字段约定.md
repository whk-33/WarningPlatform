# 数据字段约定 · 算法 ↔ 后端接口对齐

> **单一事实源**：本文档 + `algorithm/configs/schema.yaml`
> **目的**：后端开发前必须核对字段名/类型/取值，避免字段不一致导致 `KeyError` / 类型错误。
> **原则**：真实数据字段不同时，只改清洗层（`02_clean.py` 的字段映射），pipeline 通用层不动。

---

## 一、全局 ID 规范（所有表必须遵守）

| 实体 | ID 前缀 | 示例 | 说明 |
|---|---|---|---|
| 学生 student | `stu_` | `stu_100001` | 跨系统统一后的学生 ID |
| 课程 course | `crs_` | `crs_AAA` | 图节点为课程代码级（跨学期合并） |
| 课次 class_session | `cs_` | `cs_AAA_2024F_wk0` | 一次具体授课（课程×学期×周） |
| 知识点 knowledge_point | `kp_` | `kp_AAA_01` | 课程下的知识点 |
| 学习资源 resource | `res_` | `res_ppt_001` | PPT/视频/作业等 |
| 考核项 assessment | `asm_` | `asm_0000` | 作业/小测/期中/期末 |
| 题目 item | `qi_` | `qi_AAA_w3_q01` | 逐题作答（DKT 序列用） |

> **后端传入数据时**，学生 ID 必须是 `stu_` 前缀字符串，不能传纯数字或 UUID。

## 二、标签口径（二分类预警标签）

| 字段 | 类型 | 含义 | 取值 |
|---|---|---|---|
| `is_positive` | int64 | 预警标签 | `1`=有风险，`0`=正常 |
| `status` | object | 原始成绩状态 | 优秀/良好/合格/不合格/缺考/退学/休学/学业警示 |
| `risk_event_time` | int64 | 首次风险信号周次（DeepSurv 用） | `-1`=未发生风险；`0–15`=周次 |

**正例判定规则**：`status ∈ {不合格, 缺考, 退学, 休学, 学业警示} → is_positive=1`

## 六、后端对接注意事项

### 6.1 后端调用算法推理时，输入必须满足

1. 学生 ID 必须是 `stu_` 前缀字符串
2. 出勤状态只能是 `attended` / `attended_leave` / `absent` / `unknown` 之一（`unknown` 仅用于矛盾数据兜底）
3. 时间字段用 `datetime` 或可解析的字符串，周次由清洗层换算
4. 分数字段范围 0–100，缺失用 `NaN` 不要用 `-1`

### 6.2 真实数据字段不一致时的处理

| 场景 | 处理方式 | 是否需重训 |
|---|---|---|
| 字段名不同（如 `student_no` vs `stu_num`） | 在 `02_clean.py` 加字段重命名映射 | ❌ 不需要 |
| 字段类型不同（如字符串 ID vs 数字 ID） | 在清洗层统一转换格式 | ❌ 不需要 |
| 取值含义不同（如出勤用 0/1/2 vs 字符串） | 在清洗层映射到标准口径 | ❌ 不需要 |
| 缺字段（如真实数据没有 `late_minutes`） | 清洗层补默认值或降维 | ⚠️ 可能影响特征 |
| 粒度不同（如按天 vs 按周） | 清洗层聚合到标准粒度 | ❌ 不需要 |
| **标签口径不同** | **必须统一为本文档口径** | ✅ 需重训 |

> **结论**：只要标签口径不变、特征语义一致，仅字段名/类型/粒度不同，**只需改清洗层，模型无需重训**。

### 6.3 后端 ↔ 算法接口建议

后端封装算法能力时，建议的输入输出格式：

```
POST /api/warning/predict
输入: {
  "stu_id": "stu_100001",
  "course_code": "AAA",
  "semester": "2025S",
  "features": { ... }  // 或直接传原始行为日志，由后端清洗
}
输出: {
  "stu_id": "stu_100001",
  "risk_probability": 0.83,
  "risk_level": "high",
  "contributing_factors": ["attendance_rate: 0.35", "quiz_accuracy: 0.40"],
  "subgraph_nodes": [...],  // GNNExplainer 关键子图
  "subgraph_edges": [...]
}
```

## 八、公开数据集适配（OULAD）

用 `algorithm/src/data_pipeline/10_adapt_oulad.py` 把
[OULAD](https://research.stem.open.ac.uk/ouanalyse/open-dataset-more/) 转成与
`interim/` **列名完全一致**的 11 张表，下游 03/04/05 脚本无需改动。

**获取数据**：下载后把 `courses / assessments / vle / studentInfo /
studentRegistration / studentAssessment / studentVle` 7 个 csv 放到
`algorithm/data/oulad_raw/`。

**运行**（不覆盖 mock 数据）：

```powershell
python algorithm/src/data_pipeline/10_adapt_oulad.py `
    --raw algorithm/data/oulad_raw `
    --out algorithm/data/oulad/interim `
    --limit-students 2000      # 可选，先小样本跑通；0 = 全部

$env:WP_INTERIM="algorithm/data/oulad/interim"
$env:WP_PROCESSED="algorithm/data/oulad/processed"
python algorithm/src/data_pipeline/03_weekly_features.py
python algorithm/src/data_pipeline/04_knowledge_map.py
python algorithm/src/data_pipeline/05_build_graph.py
```

**标签口径**：`final_result` 映射为 `Pass→合格`、`Distinction→优秀`、
`Fail→不合格`、`Withdrawn→退学`；`is_positive` = 不合格 + 退学。

**代理字段（OULAD 缺失，已在下游保持类型可用）**

| interim 字段 | OULAD 来源 | 说明 |
|---|---|---|
| `major` | `highest_education` | 无专业字段，用最高学历代理 |
| `entrance_score` | `studied_credits` | 无入学成绩，用学分负荷代理 |
| `credits`（课程） | 该模块考核项数量 | 无学分段，且不能取常数（标准化会除零） |
| `video_watch_ratio` | 固定 0 | 无视频数据 |
| `resource_type` | `vle.activity_type` | 直接沿用 OULAD 活动类型（oucontent / ouslide / forumng / quiz …），不是 ppt/video 那套 |
| `class_session_id` | `cs_{模块}_{学期}_wk{周}` | 无"课次"，按周合成；出勤 = 周活跃 |
| `quiz_item.kp_id` | `kp_{模块}_{01..10}` | 无逐题数据，考核项按截止日期均匀分桶到 10 个伪知识点 |
| `quiz_item.score` | `score >= 40` | 用 OU 40 分及格线作正确性口径 |
| `course_prereq` | 空表 | OULAD 无课程先修链，图中该边为 0 条 |

> ⚠️ 上述代理只用于验证 pipeline 连通性。真实业务数据到位后，应替换为真实字段，
> 并重新确认标签口径（标签口径变化才需要重新训练模型）。
