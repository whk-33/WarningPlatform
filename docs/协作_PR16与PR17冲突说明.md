### 冲突 2：`admin.py` 的 `warn_list`

两边都动了同一个 `return`：

```python
# 基线（main）
return ok(get_repo().warning_list(start_time, end_time, risk_level, page_no, size, semester))

# PR #16 改成：取出 data → 循环标注干预状态 → return
data = get_repo().warning_list(...)
latest = interventions.latest_map()
for item in data["list"]:
    item["intervened"] = ...
    item["last_intervention_action"] = ...
    item["last_intervention_time"] = ...
return ok(data)

# PR #17 改成：取出 data → data.update 口径字段 → return
data = repo.warning_list(...)
data.update({"caliber": "rule_settlement", "record_unit": "student_course", ...})
return ok(data)
```

**两边都要保留，不是二选一。** 正确解法（先标注列表项，再补顶层口径字段）：

```python
@router.get("/warn/list", summary="预警列表（分页）")
def warn_list(...):
    page_no, size = _paging(page, page_size)
    repo = get_repo()
    data = repo.warning_list(start_time, end_time, risk_level, page_no, size, semester)

    # PR #16：批量标注干预状态，避免前端逐条查
    latest = interventions.latest_map()
    for item in data["list"]:
        hit = latest.get(item["warn_id"])
        item["intervened"] = hit is not None
        item["last_intervention_action"] = hit["action"] if hit else ""
        item["last_intervention_time"] = hit["created_at"] if hit else ""

    # PR #17：标注口径，避免拿 total 去对首页卡片
    data.update({
        "caliber": "rule_settlement",
        "caliber_text": "规则式 · 整学期结算 · 学生-课程级记录",
        "record_unit": "student_course",
        "semester": repo.resolve_semester(semester),
        "comparable_with_home_stat": False,
    })
    return ok(data)
```

两个改动作用在不同的键上（一个改 `list[i]` 的元素，一个改顶层字段），互不干扰，顺序无所谓。

```json
"warn_rate": 0.3456,          // 全表预警率
"occurred_rate": 0.2473,      // risk_prob 打满 1.0 的样本占比（语义待确认，见警示）
"pool_alert_rate": 0.1306     // 剔除这批人后的预警率：13.1%，落在 15%±5% 内
```

> ### ⚠️ `occurred_*` 的语义尚未证实，演示时不要断言「已经出事」
>
> 算法侧口头说明「`risk_prob = 1.0` 的行都是已发生事件（`risk_event_time <= week`）」，
> 但**我们拿到的 parquet 只有 9 列，没有 `risk_event_time`，无法核对**。
>
> 用现有 `pred_event_week` 反推也**不成立**：2014J 第 8 周 2804 行 `prob=1.0` 中，
> `pred_event_week <= 8` 的只有 **1 行（0.04%）**，`> 8` 的有 825 行（29.4%），
> 等于 `-1` 的有 1978 行（**70.5%**）。
>
> 原因是两个字段来自不同模型：`risk_prob` 来自 TFT，`pred_event_week` 来自 DeepSurv，
> 本来就不能互相印证。
>
> **前端按这个来**：
> - `pool_alert_rate` 可以说「剔除 `prob` 打满 1.0 的样本后，模型新增预警 13.1%」——这句是纯数据事实，站得住
> - **不要说**「其中 24.7% 的学生已经出事」——等算法补 `risk_state` 字段后再定性
> - 接口里 `occurred_source: "prob_proxy"` 就是提示：这是代理推断，不是权威判定
>
> 给算法侧的追问已记在 `docs/问题_风险分待确认.md`，要的就是 `risk_state` 和 `risk_event_time` 两列。
