## 一、项目概述

### 1.1 项目背景

高校学生学业失败（挂科、退学）往往不是突然发生的，而是有一个渐进过程：出勤率下降 → 小测正确率下滑 → 作业迟交 → 期末挂科。如果能在早期识别出风险学生并给出可解释的原因，就能及时干预，降低学业失败率。

现有教务系统和学习平台（雨课堂/学习通）积累了大量行为数据，但缺乏**关联分析与主动预警**能力。本平台旨在整合多源数据，通过图神经网络、知识追踪、时序生存分析、因果推断等技术，实现：

1. **提前预警**：在期末前数周识别高风险学生
2. **精准归因**：解释"为什么这个学生有风险"
3. **知识追踪**：定位学生在哪些知识点上存在薄弱环节

### 1.2 项目目标

| 目标 | 说明 |
|---|---|
| 提前 4–6 周预警 | 在第 10–12 周预测期末是否挂科，留出干预时间 |
| 可解释性 | 不仅给出风险概率，还要展示贡献最大的行为因子和关联子图 |
| 知识点级诊断 | 不仅说"你会挂科"，还要说"你在哪些知识点上没掌握" |
| 因果分析 | 区分相关与因果，回答"出勤率提高是否真的能提升成绩" |

### 1.3 目标用户

| 用户角色 | 使用场景 |
|---|---|
| 辅导员 / 班主任 | 查看班级风险学生名单，了解风险原因，进行干预 |
| 任课教师 | 查看课程整体学情，定位薄弱知识点 |
| 学生本人 | 查看个人学习画像，了解薄弱环节 |
| 教务管理者 | 查看全院/全校学业风险宏观统计 |

## 二、系统架构

### 2.1 技术分层

```
┌─────────────────────────────────────────────────────┐
│  前端（前端负责人）                                   │
│  React/Vue + 可视化库（AntV G6 / ECharts）          │
├─────────────────────────────────────────────────────┤
│  后端（后端负责人）                                   │
│  API 服务层：用户/班级/课程/预警/子图/知识点 接口     │
│  封装算法推理能力，对接数据库                          │
├─────────────────────────────────────────────────────┤
│  算法（算法负责人）                                   │
│  模型层：HAN 异质图 / DKT / TFT+DeepSurv / DoWhy      │
│  数据层：清洗 pipeline / 异质图构建 / 特征工程        │
└─────────────────────────────────────────────────────┘
```

### 2.2 数据流向

```
教务系统数据 ──┐
              ├──→ 清洗层（ID 打通/时间对齐）──→ 标准表 ──┬──→ 异质图 ──→ HAN
学习平台数据 ──┘                                          ├──→ 时序特征 ──→ TFT + DeepSurv
                                                          ├──→ DKT 序列 ──→ DKT
                                                          └──→ 宽表 ──→ DoWhy
```

## 三、功能需求

### 3.1 模块一：学业风险预警（核心）

**用户故事**：作为辅导员，我希望看到班级里有哪些学生有挂科风险，以及风险等级，以便及时干预。

| 编号 | 功能 | 说明 | 优先级 |
|---|---|---|---|
| F1.1 | 风险学生列表 | 按班级/课程展示风险学生，支持按风险概率排序、筛选 | P0 |
| F1.2 | 风险等级标签 | 高危（红）/ 中危（橙）/ 低危（黄）/ 正常（绿） | P0 |
| F1.3 | 风险概率 | 给出 0–1 的风险概率值 | P0 |
| F1.4 | 预警时间点 | 支持"第 8 周后""第 12 周后"等不同时间点的预警 | P1 |
| F1.5 | 风险趋势 | 展示该学生近几周的风险概率变化曲线 | P1 |

### 3.2 模块二：风险归因与可解释性

**用户故事**：作为辅导员，我想知道这个学生为什么被判定为高风险，以便针对性地谈话。

| 编号 | 功能 | 说明 | 优先级 |
|---|---|---|---|
| F2.1 | 关键风险因子 | 展示贡献度最高的前 5 个因子（出勤率、小测正确率、迟到次数等） | P0 |
| F2.2 | 关键关联子图 | GNNExplainer 输出：导致风险判断的关键节点和边（可视化） | P1 |
| F2.3 | 行为画像卡片 | 出勤率、小测正确率、挂科数、迟到次数等核心指标一览 | P0 |
| F2.4 | 周度趋势 | 出勤率、小测正确率随周次的变化折线图 | P1 |
| F2.5 | 多维雷达图 | 该学生 vs 正常学生均值的多维度对比 | P1 |

### 3.3 模块三：知识点级诊断（DKT）

**用户故事**：作为学生，我想知道自己在哪些知识点上掌握不好，以便重点复习。

| 编号 | 功能 | 说明 | 优先级 |
|---|---|---|---|
| F3.1 | 知识点掌握度 | 展示每个知识点的掌握概率（0–1） | P0 |
| F3.2 | 薄弱知识点列表 | 掌握度低于阈值的知识点排序 | P0 |
| F3.3 | 知识点依赖图 | 展示知识点之间的先修依赖关系 | P1 |
| F3.4 | 知识点掌握趋势 | 某知识点掌握度随周次的变化 | P2 |

### 3.4 模块四：课程学情分析

**用户故事**：作为任课教师，我想了解全班在这门课上的整体学习情况。

| 编号 | 功能 | 说明 | 优先级 |
|---|---|---|---|
| F4.1 | 课程风险分布 | 该课程高/中/低危学生人数及占比 | P0 |
| F4.2 | 班级出勤率 | 该课程每周出勤率统计 | P1 |
| F4.3 | 知识点掌握热力图 | 全班各知识点平均掌握度 | P1 |
| F4.4 | 成绩预测分布 | 期末成绩预测分布直方图 | P2 |

### 3.5 模块五：因果分析（DoWhy）

**用户故事**：作为教务管理者，我想知道出勤率是否真的因果影响成绩，以便制定考勤政策。

| 编号 | 功能 | 说明 | 优先级 |
|---|---|---|---|
| F5.1 | 因果效应估计 | 出勤率对期末成绩的平均因果效应（ATE） | P1 |
| F5.2 | 干预模拟 | 假设出勤率提升 X%，成绩提升多少 | P2 |

### 3.6 模块六：数据管理（后端）

| 编号 | 功能 | 说明 | 优先级 |
|---|---|---|---|
| F6.1 | 数据导入 | 支持导入教务系统和学习平台的 CSV/Excel 数据 | P0 |
| F6.2 | 数据清洗 | 自动执行 ID 打通、时间对齐、去重等清洗流程 | P0 |
| F6.3 | 数据质量校验 | 检查 ID 一致性、引用完整性、信号存在性 | P1 |

## 四、非功能需求

| 类别 | 要求 |
|---|---|
| 性能 | 单学生风险预测响应 < 2s；班级风险列表加载 < 5s |
| 可解释性 | 所有风险预测必须附带可解释的归因（因子或子图），不接受"黑盒"结果 |
| 数据隐私 | 学生数据脱敏存储，接口返回脱敏学号；真实数据不入 Git |
| 可复现性 | 模型训练固定随机种子，同一份数据训练结果一致 |
| 可扩展性 | 二期替换真实数据时，仅需改清洗层，pipeline 通用层不动 |

## 五、数据需求

### 5.1 数据源

| 来源 | 表 | 粒度 | 关键字段 |
|---|---|---|---|
| 教务系统 | student_info | 学生×学期 | stu_id, gender, major, entrance_score |
| 教务系统 | registration | 学生×课程 | stu_id, course_code, semester, enroll_date, drop_date |
| 教务系统 | assessment_config | 考核项 | assessment_id, course_code, type, max_score, weight |
| 教务系统 | student_assessment | 学生×考核 | stu_id, assessment_id, score, days_late, is_absent |
| 教务系统 | final_result | 学生×课程 | stu_id, course_code, final_score, status, gpa |
| 学习平台 | platform_log | 每次行为 | stu_id, course_code, resource_type, timestamp, attendance_status, late_minutes, ppt_clicks |
| 学习平台 | quiz_item_responses | 逐题 | stu_id, item_id, kp_id, score, max_score, week |
| 校历 | academic_calendar | 学期 | semester, start_date |

> 字段详细定义见 [数据字段约定.md](数据字段约定.md)

### 5.2 关键口径约定

| 口径 | 规则 |
|---|---|
| 分析主体 | 学生 × 课程开课（学期） |
| 预警标签 | `status ∈ {不合格, 缺考, 退学, 休学, 学业警示} → is_positive=1` |
| 出勤三档 | attended（到课）/ attended_leave（请假，视为合法）/ absent（缺勤） |
| 周次计算 | `week = (date - semester_start).days // 7` |
| ID 格式 | `stu_` / `crs_` / `cs_` / `kp_` / `res_` / `asm_` 前缀字符串 |

## 六、接口约定（后端 ↔ 前端）

### 6.1 风险预警接口

```
GET /api/warning/list?class_id=xxx&course_code=yyy&week=12
响应:
{
  "students": [
    {
      "stu_id": "stu_100096",
      "stu_name_masked": "张**",
      "risk_probability": 0.83,
      "risk_level": "high",
      "top_factors": [
        {"factor": "attendance_rate", "value": 0.55, "contribution": 0.35},
        {"factor": "quiz_accuracy", "value": 0.30, "contribution": 0.28}
      ]
    }
  ]
}
```

### 6.2 学生风险画像接口

```
GET /api/warning/student/{stu_id}?week=12
响应:
{
  "stu_id": "stu_100096",
  "risk_probability": 0.83,
  "risk_level": "high",
  "metrics": {
    "attendance_rate": 0.55,
    "quiz_accuracy": 0.30,
    "fail_count": 3,
    "avg_late_minutes": 12
  },
  "course_scores": [...],
  "attendance_trend": [...],
  "quiz_trend": [...],
  "radar": {...}
}
```

### 6.3 关键关联子图接口（GNNExplainer）

```
GET /api/warning/student/{stu_id}/subgraph
响应:
{
  "nodes": [
    {"id": "stu_100096", "type": "student", "label": "目标学生"},
    {"id": "crs_AAA_2024F", "type": "course", "label": "高等数学"}
  ],
  "edges": [
    {"src": "stu_100096", "dst": "crs_AAA_2024F", "type": "enrolled_in", "weight": 0.8}
  ]
}
```

### 6.4 知识点诊断接口

```
GET /api/dkt/student/{stu_id}/course/{course_code}
响应:
{
  "knowledge_points": [
    {"kp_id": "kp_AAA_01", "name": "极限", "mastery_prob": 0.32, "is_weak": true},
    {"kp_id": "kp_AAA_02", "name": "导数", "mastery_prob": 0.75, "is_weak": false}
  ]
}
```

## 七、阶段规划

### 阶段一：数据基座搭建（已完成 ✅）

**目标**：用 mock 数据完成"脏原始 → 干净标准表 → 模型可吃"的全链路搭建。

| 任务 | 交付物 | 状态 |
|---|---|---|
| T0 Mock 数据生成 | `00_generate_mock.py` + 11 张脏表 | ✅ |
| T1 清洗 + ID 打通 | `02_clean.py` + 11 张干净 Parquet | ✅ |
| T2 异质图构建 | `05_build_graph.py` + 5 节点 9 边图 | ✅ |
| T3 时序特征 | `03_weekly_features.py` + TFT 宽表 25632×29 | ✅ |
| T4 知识点 + DKT | `04_knowledge_map.py` + DKT 序列 | ✅ |

**验收**：pytest 30/30 全绿，完整性检查 102 PASS。

### 阶段二：模型训练（待启动）

| 模型 | 输入 | 输出 | 优先级 |
|---|---|---|---|
| HAN 异质图 | graph_nx.json | 风险概率 | P0 |

## 九、风险与依赖

| 风险 | 影响 | 应对 |
|---|---|---|
| 真实数据获取延迟 | 阶段四无法启动 | 阶段一/二用 mock 数据并行推进 |
| 真实数据字段与 mock 不一致 | 清洗层需重写 | 字段约定文档先行，清洗层做字段映射 |
| 模型效果不达标 | 预警准确性不足 | 增加特征、调整模型、考虑集成 |
| 前后端接口字段不一致 | 联调报错 | 接口约定文档 + 字段对齐 review |
