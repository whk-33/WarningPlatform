## 2. parquet 字段契约（11 字段；原 9 字段不变，新增 2 列向后兼容）

`stu_id / course_code / semester / week(int8,0-15) / risk_prob(float32,0-1) / risk_level(int8,0/1/2) / risk_level_name(低/中/高) / pred_event_week(int8,-1=学期内无风险) / top_factors(JSON 字符串) / risk_state(int8,0/1) / risk_score(float32)`

- `week` 一律 0 起，前端展示层 `+1`；后端不改写
- `risk_prob` 0-1，**未做 Platt/isotonic 概率校准**，只作排序分；语义是 P(之后还会出事 | 尚未出事)，不是“挂科概率”
- `risk_state`：`0`=模型预测，`1`=风险事件已发生。**`risk_state=1` 时 `risk_prob` 恒为 1.0，这是占位值不是模型打分**，前端必须展示为“已发生”，不要显示“风险 100%”
- `risk_score`：未饱和原始 logit，仅 `risk_state=0` 有值（已发生为 null）。**排序/分档请用它**，与 `risk_prob` 严格单调；风险池内无并列（w8 约 99.2% 取值互异）
- `pred_event_week = -1` 通常是**本学期无风险**（语义值，不是 bug）；但推理桥在**无法判定**时（缺 `deepsurv_pred.parquet` 且现场推理不可用）同样返回 -1，二者在字段上不可区分
- 因此展示规则：`pred_event_week = -1` 且 `risk_prob >= 0.5` 时视为**未知**，前端不得显示“预计无风险”，改显“暂无预计周”；仅 `risk_prob < 0.5` 时可展示“学期内无风险”
- 离线表无此问题：`risk_scores.parquet` 的 `pred_event_week` 恒由 M3 产物 `deepsurv_pred.parquet` 生成，该文件属打分必需输入
- `top_factors` 建议后端 `json.loads` 成数组再返回（B5）；contrib 可能 <100%，**前端不要强制归一**
- **期末周（week=15）**：该周已无“未来风险”标签，阈值沿用第 14 周，模型侧几乎不再新增预警（风险池预警 0.21%）；该周展示应以 `risk_state=1`（已发生）为主

## 3. 五个风险接口

### 3.1 `GET /api/risk/weekly?stu_id&course_code&semester&week`
单周风险。响应样例见 [mock_api/weekly.json](mock_api/weekly.json)。
字段 = parquet 9 字段中 8 个（`top_factors` 解析为数组）。

### 3.2 `GET /api/risk/student/{stu_id}?semester=`
全学期曲线，**一次返回数组**（F1：不要前端循环 16 次）。样例见 [mock_api/student.json](mock_api/student.json)。
`weeks[]` 每元素含 `week/risk_prob/risk_level/risk_level_name/pred_event_week/top_factors/course_code`；多门课取当周最高风险那门（与推理桥 `predict_student` 同口径）。

### 3.3 `GET /api/risk/factors?stu_id&course_code&semester&week`
归因。样例见 [mock_api/factors.json](mock_api/factors.json)。
`top_factors[]`：`{factor, value, contrib}`，最多 3 个，按 contrib 降序。

### 3.4 `GET /api/admin/risk/list?semester&week&level&page&size`
管理员分页列表，按 `risk_score`（未饱和 logit）降序，`risk_score` 为空（已发生）单独分组。样例见 [mock_api/admin_list.json](mock_api/admin_list.json)。
`level` 可选过滤 0/1/2；响应含 `page/size/total/items[]`。
学生级聚合沿用 [接口约定.md §3.3](接口约定.md#L135-L148)：`risk_level=max(课程级)`，但**聚合前剔除 `risk_state=1` 的行**，否则学生会恒为高危。

### 3.5 `GET /api/admin/risk/stat?semester&week`
等级分布。样例见 [mock_api/admin_stat.json](mock_api/admin_stat.json)。

| 指标 | 算法 | 用途 |
|---|---|---|
| `alert_rate` | `(level_1 + level_2) / total` | 全表口径，**含已发生**，会随周次自然升高（w8≈34%、w15≈53%） |
| `alert_rate_at_risk` | 仅 `risk_state=0` 行上算 | 产品口径，目标 15%±5%（w8 实测 15.4%） |
| `occurred_rate` | `risk_state=1 / total` | 已发生占比（w8≈22%、w15≈53%） |

三者满足 `alert_rate ≈ occurred_rate + alert_rate_at_risk × (1 − occurred_rate)`。**对外汇报预警率请用 `alert_rate_at_risk`，不要用 `alert_rate`。**

## 4. 推理桥（新学生兜底，B6）

```bash
# 三模式（stdout 单行 JSON，成功 exit 0；失败 exit 1 且输出 {"error","mode"}）
python algorithm/src/serving/30_online_risk.py weekly   --stu_id <id> --course_code <c> --semester <s> --week <0-15>
python algorithm/src/serving/30_online_risk.py student  --stu_id <id> --semester <s>
python algorithm/src/serving/30_online_risk.py subgraph --stu_id <id> --semester <s> [--week 8]
```

- **后端进程不要 import torch**：只 subprocess 调用，模型内存在子进程结束即释放
- 延迟：缓存命中约 15ms，新学生首次约 800ms；建议后端设 5s 超时 + 404 兜底
- 错误契约：exit≠0 或 stdout 含 `error` 键 → 后端按 503/404 处理，不要解析半截 JSON

### 4.1 环境前置：必须先验证 torch 能加载

```bash
python -c "import torch; print(torch.__version__)"   # 必须能打印版本号，否则推理桥不可用
```

**已知故障：Windows 11 的 Smart App Control 会拦截未签名的 `.pyd`**
症状是报 `ImportError: DLL load failed while importing _C: 应用程序控制策略已阻止此文件`（不是缺依赖，不必反复重装 torch/torchvision）。

诊断三步：

```powershell
# 1. 确认 SAC 是否在强制执行（1=开，0=关，2=评估模式）
Get-ItemProperty 'HKLM:\SYSTEM\CurrentControlSet\Control\CI\Policy' | Select VerifiedAndReputablePolicyState
# 2. 看被拦的具体文件（事件 Id 3033/3077 会写明路径）
Get-WinEvent -LogName 'Microsoft-Windows-CodeIntegrity/Operational' -MaxEvents 10
# 3. 确认该 pyd 是否未签名
Get-AuthenticodeSignature "<python>\Lib\site-packages\torch\_C.cp3xx-win_amd64.pyd" | Select Status
```

两条可选路径（部署机二选一，均由环境负责人决定）：

| 路径 | 做法 | 代价 |
|---|---|---|
| 关 Smart App Control | 设置 → 隐私和安全性 → Windows 安全中心 → 应用和浏览器控制 → 智能应用控制 → 关闭，重启 | **不可逆**，微软明确只能重置/重装系统才能恢复 |
| 用带签名的发行版 torch | 例如 Anaconda 渠道的 pytorch（`_C.pyd` 有 `Anaconda, Inc.` 签名，可通过 SAC） | 需与该发行版 Python 统一解释器；若同机存在多份 `libiomp5md.dll` 需先清理（`KMP_DUPLICATE_LIB_OK=TRUE` 只是绕过、会硬崩，不要当解决方案） |

> 现状记录（2026-11-09，算法侧开发机）：SAC 开启，pip 装的 Python 3.13 torch `_C.pyd` 为 NotSigned → 推理桥本机不可运行；非 torch 的 61 项测试正常。**推理桥需在通过上述验证的机器上做联调，不要在未验证的机器上判定接口有问题。**

## 5. 数据源切换（真实数据试点）

1. 新数据按 `docs/数据字段约定.md` 清洗后放入新目录（如 `processed_school_v1/`）
2. 依次跑 `20_score_offline.py`（打分）→ `32_quality_checks.py`（PSI 门禁）→ 通过后原子替换 `risk_scores.parquet`（`31_weekly_run.py` 已封装此流水线）
3. 后端用 `WP_PROCESSED` 指向新目录，无需改代码
4. PSI > 0.25 时门禁阻断、保留旧表，阈值强制重校（C4：目标预警率 15%±5%）
