> 面向：前端同学。契约母文档是 `docs/接口约定.md` §5.16–§5.20，本文只讲**怎么接、坑在哪**，不重复字段表。
> 后端状态：已合并到 `main`（PR #14），24 个后端测试全绿，可直接起服务联调。新增风险演示账号 `riskdemo`。

## 0. 一分钟结论

| 问题 | 答案 |

## 1. 起服务 + 拿 token（可直接复制跑）

```bash
cd backend
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
```

```bash
# 管理员 token
curl -s -X POST http://127.0.0.1:8000/api/login/admin \
  -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"wp123456"}'
```

响应里取 `data.token`，后续请求带 `Authorization: Bearer {token}`。

**先用这条确认后端吃的是哪份数据**：

```bash
curl -s http://127.0.0.1:8000/api/health
```

```json
{
  "data_source": "parquet",
  "risk_source": "mock",
  "risk": { "source": "mock", "rows": 35, "semesters": ["2014B"], "sample_based": true }
}
```

`risk_source=mock` → 风险接口读的是 `docs/mock_api/` 样本，只有 20 个高危学生、1 个学生的 16 周曲线。此时**列表翻不到第 2 页、低/中风险筛出来是空**，不是 bug。

## 2. `src/api/index.js` 直接抄这 5 个函数

```js
/* ---------------- 阶段四 · 风险（与上面 15 个并行，不替换） ---------------- */

// 16 周曲线：一次拿全，别循环调
export function getRiskCurve(stuId, params) {
  return request.get(`/risk/student/${stuId}`, { params })
}

// 单周风险
export function getRiskWeekly(params) {
  return request.get('/risk/weekly', { params })
}

// 单周归因 top3
export function getRiskFactors(params) {
  return request.get('/risk/factors', { params })
}

// 本周风险榜（管理员）
export function getAdminRiskList(params) {
  return request.get('/admin/risk/list', { params })
}

// 等级分布 + 预警率（管理员）
export function getAdminRiskStat(params) {
  return request.get('/admin/risk/stat', { params })
}
```

⚠️ 注意两点：

1. 路径是 `/risk/...` 和 `/admin/risk/...`，**不是** `/api/risk/...`——`request.js` 的 `baseURL` 已经带了 `/api`；
2. `/admin/risk/list` 返回的是 `{ items, total, page, size }`，和现有列表的 `{ list, total, page, page_size }` **不一样**。`request.js` 的拦截器已经把 `{code,msg,data}` 拆过包，页面拿到的是 `data` 本身（现有页面就是 `data.list`），所以兜一下即可：

```js
const rows = data.items ?? data.list
const perPage = data.size ?? data.page_size
```

## 3. 五个接口速查

| 接口 | 关键参数 | 返回要点 |
|---|---|---|
| `GET /risk/student/{stu_id}` | `semester`（可选） | `weeks[]` 16 个点，按 `week` 升序；顶层带 `student_name` / `class_name` |
| `GET /risk/weekly` | `stu_id` `course_code` 必填，`semester` `week` 可选 | 单条 8 字段 + `top_factors` 数组 |
| `GET /risk/factors` | 同 `weekly` | `top_factors` 已按 `contrib` 降序，最多 3 个 |
| `GET /admin/risk/list` | `semester` `week` `level` `page` `size` | 按 `risk_prob` 降序，项里**带姓名/专业/班级**，但没有 `top_factors` |
| `GET /admin/risk/stat` | `semester` `week` | `level_0/1/2` + `alert_rate` + `list_available` |

参数名易错：列表过滤等级叫 **`level`**（不是 `risk_level`）；分页 `size` 和 `page_size` **两个都收**，传哪个都行。

## 4. 七条字段红线

| # | 规矩 | 错了会怎样 |
|---|---|---|
| 1 | `week` 是 **0–15**，横轴标签写 `week + 1` | 整条曲线左移一周，第一周显示成"第0周" |
| 2 | `pred_event_week === -1` → 显示"本学期内无风险" | 会渲染成"第 0 周有风险事件"，语义完全反了 |
| 3 | `risk_prob` 是 **0–1 小数**，前端转百分数 | 直接 `%` 会显示 0.47% |
| 4 | 风险接口用 **`risk_level_name`（低/中/高）**；旧页面用 `risk_level_text`（正常/警惕/高危） | 两套词混进一个图例，老师会问"低是哪来的" |
| 5 | `top_factors[].contrib` **总和可能 < 1**，别强制归一到 100% | 条形图长度失真 |
| 6 | 分页器用 `list_available`，不要用 `total` | mock 下 `total=7804`、实际只有 20 条，翻页全是空的 |
| 7 | 风险榜/曲线的姓名直接用接口自带的 `student_name`，**别拿 `stu_id` 去 join 旧学生列表** | 两套学生 ID 零交集（`100001…` vs `stu_100621…`），join 完姓名全是空 |

真实响应（已实测，`week=8`）：

```json
{
  "code": 200, "msg": "success",
  "data": {
    "stu_id": "stu_100621", "course_code": "CCC", "semester": "2014B", "week": 8,
    "risk_prob": 1.0, "risk_level": 2, "risk_level_name": "高", "pred_event_week": -1,
    "top_factors": [
      { "factor": "出勤率",     "value": 0.44, "contrib": 0.517 },
      { "factor": "课件点击数", "value": 26.0, "contrib": 0.21  },
      { "factor": "测验正确率", "value": 0.0,  "contrib": 0.132 }
    ],
    "data_source": "mock"
  }
}
```

## 5. 建议落点

| 新接口 | 落在哪 | 建议做法 |
|---|---|---|
| `/risk/student/{stu_id}` | `views/admin/StudentList.vue` 详情弹窗，或 `views/student/Home.vue` | ECharts 折线；x 轴 `week+1`，点的 tooltip 直接用该点的 `top_factors`（省一次请求）。**弹窗入口要用风险数据自己的 `stu_id`**（即从风险榜点进来），旧列表的学生 ID 查不到，见 §8 |
| `/risk/weekly` | 曲线点击后的详情卡 | 只在需要"换课程/换周"时才调 |
| `/risk/factors` | 归因横条图 | 已有降序，直接按数组顺序画 |
| `/admin/risk/stat` | `views/admin/Home.vue` 饼图旁 | 与现有 `home/stat` **并列**展示，方便对比两套口径 |
| `/admin/risk/list` | `views/admin/StudentList.vue` 新增 tab | 叫"本周风险榜"，跟现有"学期末结论"区分开；行内姓名直接用 `student_name`，点行用该行 `stu_id` 打开详情弹窗 |

演示可用数据：`stu_100621` / `course_code=CCC` / `semester=2014B` / `week=8`（mock 里唯一有完整 16 周曲线的学生）。

## 6. 学生端联调用 `riskdemo` 账号

普通演示学生账号的 `stu_id` 是 `stu_100016` 这类（200 人演示集），而风险数据覆盖的是 `stu_100621` 这类（OULAD 真实学生），**两边没有交集**——用普通学生账号调自己的曲线必然是 `404`。

后端为此加了一个专用账号，启动时自动绑定到风险数据里**曲线最完整**的学生：

| 角色 | 账号 | 密码 | 绑定 |
|---|---|---|---|
| 风险演示学生 | `riskdemo` | `wp123456` | `stu_100621`（mock，16 周齐全）|

```bash
# 学生端联调就这么登
curl -s -X POST http://127.0.0.1:8000/api/login/student \
  -H 'Content-Type: application/json' \
  -d '{"student_id":"riskdemo","password":"wp123456"}'
```

拿到 token 后，`data.stu_id` 就是要传给 `/risk/student/{stu_id}` 的值（当前是 `stu_100621`），**不要写死**，从登录响应里取。

实测这条曲线很好演示：第 1 周 `低 / 0.4666` 一路涨到第 16 周 `高 / 1.0`，一共 16 个点、`partial=false`。

权限边界没变（已实测）：

| 请求 | 结果 |
|---|---|
| `riskdemo` 查自己 | `200`，16 个点 |
| `riskdemo` 查别人 `stu_100016` | `403 只能查看自己的风险数据` |
| `riskdemo` 调 `/admin/risk/*` | `403` |
| 普通学生 `100016` 查自己 | `404`（他在风险数据里没有记录，属预期） |

数据源换成真实 parquet 后，`riskdemo` 的绑定会自动改成新数据里曲线最完整的学生，前端逻辑不用动。

## 8. 你们 11-17 定的三条口径，后端怎么配合

| 议题 | 前端结论 | 后端动作 | 你们要注意 |
|---|---|---|---|
| 等级文案 | 两套并存：风险页 `risk_level_name`（低/中/高），旧页 `risk_level_text`（正常/警惕/高危），同一图例内不混用 | **零改动**，本来就是两套字段 | 别写 `{0:'低',1:'中',2:'高'}` 这类映射，直接用接口返回的字符串 |
| 曲线形态 | 内嵌，不新增独立页；管理员在"学生详情"弹窗看，学生在首页卡片看 | v1.2 给曲线顶层补了 `student_name` / `class_name`，弹窗标题不用再查一次 | **弹窗入口必须是风险数据的学生**：从"本周风险榜"点行进来，或传风险榜里的 `stu_id`。从旧学生列表（`100001…`）进来查不到数据，这是两套 ID 的问题，不是接口坏了 |
| 因子条形图 | 单色主蓝，长度按 `contrib`；三色只用于等级标签和折线点 | **零改动**，`contrib` 是算法原始权重 | 实测 top3 合计 0.859（0.517 / 0.21 / 0.132），最长条只到 52% 宽。想要视觉更饱满可以按 top1 归一化**只做视觉**，但不要把归一化后的数字标成"占比"；另外给条形加个最小宽度（如 6px），否则 0.13 那根几乎看不见 |

## 9. 全量数据已接入（2026-11-17 更新）

后端已切到算法侧真实产物：**28,785 名学生 / 521,488 行周度风险 / 4 个学期（2013B、2013J、2014B、2014J）**，
`/api/health` 里 `data_source=parquet`、`risk_source=parquet`、`sample_based=false`。

这对前端有 5 个直接影响：

| # | 变化 | 你要做什么 |
|---|---|---|
| 1 | **`week` 缺省值从"最新周"变成第 8 周**（期中） | 不传 `week` 时拿到的是第 8 周。最后一周年限高危率会突增到 50%+，演示请用默认值 |
| 2 | **学生账号能查到自己了** | 普通学号账号（如 `130045`）登录后直接调 `/api/risk/student/{list 里的 stu_id}` 返回 `200`。`riskdemo` 仍可用，但不是必须 |
| 3 | **`total` 与 `list_available` 相等** | 分页逻辑不用改，`list_available` 照旧用；不会再有"翻页全空" |
| 4 | **`avg_score` 可能是 `null`** | 口径是剔除退学；高危榜按风险降序，退学学生排最前，首页很容易看到 `null`。请渲染成 `—`，不要显示 `0` |
| 5 | **列表规模从 20 变 11260** | 首屏别一次性拉全量，`size` 建议 20–50；搜索走后端 `keyword`，不要前端过滤 |

对照实测（2014J 第 8 周）：

```
risk/stat  → total=11260, level_0=7355, level_1=743, level_2=3162, alert_rate=0.3468
risk/list  → total=11260, list_available=11260
学生端      → 5/5 个随机演示账号查自己，全部 200，week_count=16
旧接口      → 16 项冒烟全过（home/stat、student/list、student/detail、gnn/graph、warn/list、warn/report……）
```
