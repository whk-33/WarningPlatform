## 一、相对前端接口文档的变更（必须先看）

| # | 前端原文档 | 本约定 | 原因 |
|---|---|---|---|
| 1 | `/api/warn/list`、`/api/student/list`、`/api/gnn/graph` | `/api/admin/warn/list`、`/api/admin/student/list`、`/api/admin/gnn/graph` | 学生端也有 `warn/list`、`gnn/graph`，不加 `admin/` 会路由冲突 |
| 2 | 列表返回裸数组 | 返回 `{list, total, page, page_size}` | OULAD 全量 3 万学生，裸数组前端没法分页 |
| 3 | GNN 返回全图 | 默认只返回 top 50 高风险学生，支持 `limit_students` | 1141 节点 / 14 万边直接丢给 AntV G6 会卡死 |
| 4 | `student_id` 既指学号又指学生 | **`student_id` 统一 = 学号**，另给 `stu_id`（`stu_` 前缀内部 ID） | 一个标识只表达一件事；图节点 id 也用学号，点击即可查详情 |
| 5 | 风险等级 `正常/警惕/高危` | 同左，但底层是 `risk_level: 0/1/2`，同时返回 `risk_level_text` | 前端只渲染文本，不写 if-else 判断 |
| 6 | 未定义分页/错误码 | 见 §2.5、§2.4 | — |
| 7 | `warn_count` 口径不明 | `warn_count = 高危 + 警惕`，另给 `high_count / mid_count` | 首页卡片和饼图要能对上 |
| 8 | `/api/logout` 未定义语义 | 返回 200，服务端不失效 token，前端清 localStorage | JWT 无状态，课程项目不做黑名单 |

## 二、通用约定

### 2.1 请求前缀与地址

```
开发环境  http://127.0.0.1:8000
接口前缀  /api
Swagger   http://127.0.0.1:8000/docs
```

### 2.2 认证

```
Authorization: Bearer {token}
```

- 除 `/api/login/*`、`/api/health`、`/api/meta/*` 外，全部需要 token。
- `role` 只有两种：`admin` / `student`。
- **学生端所有接口的 `stu_id` 一律从 token 取**，前端传任何 `student_id` 都不生效，杜绝越权。
- token 有效期 12 小时（`WP_TOKEN_HOURS` 可调），过期返回 `401`。

### 2.3 统一响应

成功：

```json
{ "code": 200, "msg": "success", "data": {} }
```

失败（HTTP 状态码与 `code` 一致，方便 axios 拦截器统一处理）：

```json
{ "code": 403, "msg": "需要管理员权限", "data": null }
```

### 2.4 错误码

| code | HTTP | 含义 | 前端动作 |
|---|---|---|---|
| 200 | 200 | 成功 | — |
| 400 | 400 | 参数不合法（如学期不存在） | 提示 msg |
| 401 | 401 | 未登录 / token 过期 / 账号密码错误 | 清 token，跳登录页 |
| 403 | 403 | 角色越权（学生访问 admin 接口） | 提示 + 回自己首页 |
| 404 | 404 | 学生 / 预警记录不存在 | 提示 msg |
| 422 | 422 | 参数校验失败（缺参、类型错） | 提示 `data[0].field` |
| 500 | 500 | 服务端异常 | 提示"服务异常" |

### 2.5 分页

列表接口统一：

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `page` | int | 1 | 从 1 开始 |
| `page_size` | int | 20 | 上限 100，超出自动截断为 100 |

响应：

```json
{ "list": [], "total": 200, "page": 1, "page_size": 20 }
```

### 2.6 时间与学期

| 项 | 约定 |
|---|---|
| 学期格式 | `2024F`（秋）/ `2025S`（春），`semester` 参数缺省取**最新学期** |
| 学期起始日 | 秋 `09-02`，春 `02-24`（与 `schema.yaml` 一致） |
| 时间格式 | `YYYY-MM-DD HH:mm`，如 `2025-06-09 09:00` |
| 周次 | `semester_week`，`0–15`，`-1` 表示未发生风险事件 |

### 2.7 风险等级

| risk_level | risk_level_text | 含义 | 前端 |
|---|---|---|---|
| 0 | 正常 | 无风险课程 | 绿 |
| 1 | 警惕 | 有课程不合格 | 橙 |
| 2 | 高危 | 退学 / 休学 / 学业警示 | 红 |

> 底层口径来自 `schema.yaml` 的 `label.risk_level`；OULAD 映射为 `Withdrawn→2`、`Fail→1`、`Pass/Distinction→0`。

### 2.8 字段命名

- **全部 snake_case**（`student_id`、`risk_level`、`warn_reason`）。
- 前端现有代码里是 camelCase（`stuId`、`warnLevel`），需要改，见 §6。

## 三、业务口径（这份文档最该被 review 的部分）

### 3.1 分析主体

`学生 × 课程 × 学期`。一门课一条 `final_result` 记录；同一个学生在不同学期是不同批次。

### 3.2 `avg_score`（平均分）

```sql
WHERE status <> '退学'            -- 剔除退学
  AND semester = {当前学期}        -- 只取当学期，不跨学期
avg(COALESCE(final_score, 0))     -- 缺考按 0 计入，不拉高均值
```

- 当学期全部课程都是退学 → 返回 `null`（前端显示 `—`），**不要当 0 处理**。
- OULAD 适配后实际只有 `合格/优秀/不合格/退学` 四种状态，`缺考` 不会出现，规则保留给真实数据。

### 3.3 学生级风险聚合

课程级 `risk_level` → 学生级，三个字段各管一件事：

| 字段 | 算法 | 用途 |
|---|---|---|
| `risk_level` | `max(课程级)` | **判定是否预警**，保召回 |
| `risk_score` | `Σ(risk_levelᵢ × creditsᵢ) / Σcreditsᵢ / 2` | **列表排序**，0~1 |
| `high_course_count` | `count(课程级 = 2)` | 优先级，"1 门崩" vs "3 门崩" |

为什么不用纯加权：会稀释单科崩盘（4 门课 1 门挂、3 门及格 → 加权后只是"警惕"），且 OULAD 的 `credits` 是代理值（考核项数量），权重本身不可信。
为什么不用纯 max：会被单门"杀手课"污染，高危名单可能一大半是同一门课的学生。

> ⚠ **预警率提醒**：`max` 聚合会让学生级预警率显著高于课程级。演示数据 200 人里约 60% 学生至少有一门风险课。前端列表建议**默认只看 `risk_level=2`**，"警惕"单独做成"关注"入口。

### 3.4 预警记录（`warn_id` 从哪来）

数据源里没有"预警记录表"，由后端按课程级风险生成：

```
warn_id   = "W" + md5(f"{stu_id}|{course_code}|{semester}|{week}")[:9].upper()
warn_time = semester_start(semester) + week * 7 天（时间取 09:00）
week      = risk_event_time，缺失或 -1 时按 15 处理
```

- **幂等**：同一 (学生, 课程, 学期, 周) 永远得到同一个 `warn_id`，重复跑批不会产生重复记录。
- 只有 `risk_level >= 1` 的课程才生成预警；一个学生多门课风险 → 多条预警记录。

### 3.5 归因来源

模型（HAN/TFT/GNNExplainer）还没训练，`warn_reason`、`factors`、`suggestions` 目前**全部是规则产出**，响应里带：

```json
{ "source": "rule" }
```

GNNExplainer 上线后改成 `"model"`，字段结构不变。**答辩时不要说成"模型解释"。**

### 3.6 图裁剪

| 场景 | 规模 | 说明 |
|---|---|---|
| 管理员全局图 | 默认 50 学生 + 其课程，约 60–70 节点 | `limit_students` 可调，上限 200 |
| 学生个人图 | 本人 + 当学期课程，≤ 10 节点 | 1 跳，不做 2 跳展开 |

`meta.truncated = true` 表示还有更多学生没返回，前端可提示"仅展示风险最高的 N 名学生"。

## 五、接口详情

### 5.1 管理员登录

`POST /api/login/admin`

请求：

```json
{ "username": "admin", "password": "wp123456" }
```

响应 `data`：

```json
{
  "token": "eyJhbGciOiJIUzI1NiIs...",
  "username": "admin",
  "name": "管理员",
  "role": "admin"
}
```

错误：`401` 账号或密码错误（不区分是账号不存在还是密码错，避免账号枚举）。

### 5.2 学生登录

`POST /api/login/student`

请求（`student_id` 填**学号**，不是 `stu_` 内部 ID）：

```json
{ "student_id": "20220100", "password": "wp123456" }
```

响应 `data`：

```json
{
  "token": "eyJ...",
  "student_id": "20220100",
  "student_no": "20220100",
  "stu_id": "stu_100100",
  "name": "学生100",
  "role": "student"
}
```

### 5.3 退出登录

`POST /api/logout` → `data: null`

JWT 无状态，服务端不做失效；前端清 `localStorage.token` 与 `role` 即可。

### 5.4 首页统计

`GET /api/admin/home/stat?semester=2025S`

| 参数 | 必填 | 说明 |
|---|---|---|
| `semester` | 否 | 缺省取最新学期 |

响应 `data`：

```json
{
  "semester": "2025S",
  "total_student": 200,
  "warn_count": 121,
  "high_count": 69,
  "mid_count": 52,
  "normal_count": 79,

```

口径：`warn_count = high_count + mid_count`，`total_student = warn_count + normal_count`。

`GET /api/admin/warn/report?warn_id=W93E9CB484`

响应 `data`：

```json
{
  "warn_id": "W93E9CB484",
  "source": "rule",
  "student": { "student_id": "20220100", "name": "学生100", "avg_score": 58.4, "risk_level_text": "高危", "..." : "同 5.6" },
  "course": {
    "course_code": "BBB",
    "course_name": "线性代数",
    "final_score": 30.6,
    "status": "退学",
    "semester_week": 14,
    "warn_time": "2025-06-09 09:00"
  },
  "summary": "学生100 在《线性代数》上判定为高危，主要因为线性代数期末成绩为 30.6（阈值 60.0）；当学期 3 门课中 2 门高危、2 门不及格。",
  "factors": [
    { "factor": "final_score", "label": "线性代数期末成绩", "value": 30.6, "threshold": 60.0, "contribution": 0.49, "direction": "lower_is_worse" },
    { "factor": "fail_count", "label": "不及格课程数", "value": 2, "threshold": 0, "contribution": 0.667, "direction": "higher_is_worse" }
  ],
  "trend": [{ "week": 0, "attendance_rate": 0.86 }, { "week": 1, "attendance_rate": 0.821 }],
  "trend_source": "estimated",
  "course_list": [],
  "suggestions": ["优先处理《线性代数》《高等数学》：..."],
  "suggest_text": "优先处理《线性代数》《高等数学》：...；出勤率 58%，低于 60% 警戒线，先把到课率拉起来。",
  "subgraph": { "nodes": [], "edges": [], "meta": { "semester": "2025S", "node_count": 4, "edge_count": 3 } }
}
```

字段说明：

| 字段 | 说明 |
|---|---|
| `source` | `rule` = 规则归因；`model` = 模型归因（阶段三才有） |
| `factors[].contribution` | 0~1 的"距阈值缺口"，只保证排序合理，**不是模型权重** |
| `trend_source` | `platform_log` = 真实周度聚合；`estimated` = 按当前值线性估算 |
| `subgraph` | 与 `/api/student/gnn/graph` 同结构，可直接喂 G6 |

错误：`404` 预警记录不存在。

## 七、字段 ↔ 数据源映射（后端实现依据）

| 接口字段 | 数据源 | 备注 |
|---|---|---|
| `student_id` | `student_info.student_no` | 合成学号，唯一 |
| `stu_id` | `student_info.stu_id` | `stu_` 前缀，算法侧主键 |

## 九、已知限制（写进答辩材料，别被问穿）

| # | 限制 | 影响 | 计划 |
|---|---|---|---|
| 1 | 归因是规则产出，不是模型 | `factors` 不能叫"模型解释" | 阶段三接 GNNExplainer，字段不变 |
| 2 | `attendance_rate` / `quiz_accuracy` 无真实行为日志时是代理值 | 画像页指标只能看趋势不能当真值 | 接 OULAD `studentVle` 后替换 |
| 3 | 知识点诊断接口未实现 | 前端也还没有对应页面 | 阶段三补 `/api/dkt/...`，表已建（`kp_mastery`） |
| 4 | `credit` 是代理值 | 加权排序的权重不够"真实" | 真实数据到位后替换 |
| 5 | 预警记录由跑批生成，非实时 | 数据更新后需重跑 | 阶段二上 Celery 定时任务 |
| 6 | 学生姓名/班级是合成字段 | 不能对外宣称真实学生信息 | 界面常驻"演示数据"标识 |
